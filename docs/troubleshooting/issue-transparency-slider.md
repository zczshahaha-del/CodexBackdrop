# 菜单透明度滑杆偶尔无法拖动

日期：2026-10-08。

主要问题记录：[GitHub Issue #2](https://github.com/zczshahaha-del/CodexBackdrop/issues/2)。实际鼠标拖动仍待验收，Issue 保持开放。

## 现象与环境

- 用户报告原生菜单里的透明度滑杆经常拖不动，百分比也不变；截图停在 10%。
- 出现问题时版本为 3.5.0（build 9），macOS 27.0.1；截图中的滑杆停在 10%。
- 本次在 `codex/fix-transparency-slider` 分支修复，保留既有设置。

## 排查与验收

- 原实现通过主队列回调自动打开菜单。用原生运行循环复现：在该回调中的菜单事件跟踪循环里，后续主队列完成回调无法执行，直到菜单关闭。
- 原菜单开启了动作自动验证，更新菜单后，没有 action 的滑杆条目会被系统禁用。
- 应用背景时原来会禁用滑杆；现在始终允许调整并保存数值，背景应用完成后发送最后一次选择。
- 透明度请求合并并串行执行，避免较早的慢请求覆盖后续数值。清晰模式也使用同一更新通道，避免在主线程等待网络检查。

## 修复与验证

- 3.5.1（build 10）：手动管理菜单启用状态；自动打开菜单和后台完成回调使用支持菜单跟踪的主运行循环；透明度滑杆不再随后台应用被禁用。
- `bash scripts/test-menu.sh`：原生菜单条目保持可交互，嵌套菜单跟踪期间回调及时执行，连续调整、慢请求、后台恢复和失败后继续调整均通过。
- 独立原生测试窗口中，菜单保持打开时通过辅助功能将滑杆从 10% 调到 95%，再回到 10%，百分比同步变化；测试未连接 Codex，也未修改用户设置。
- UI 自动化工具无法在自定义菜单条目上执行坐标拖动；未把辅助功能赋值测试当成实际鼠标拖动验收。偶发问题是否完全消失仍需用户实际拖动确认。
